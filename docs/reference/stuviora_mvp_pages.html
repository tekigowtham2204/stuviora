Blueprint planned 40 pages. These 9 are cut from the MVP. Each one is either redundant, over-engineered for launch, or replaceable with a simpler approach.
9 pages cut — with the exact reason
✕/how-it-worksCollapse into homepage sections. A separate page for this is a distraction before you have users.
✕/auth/signupWait — keep this. Role picker IS needed. Remove the separate /signup/student and /signup/client IF you do role-on-signup. Actually keep all 3.
✕/student/portfolioPortfolio is auto-generated and displayed on /freelancer/[username]. No separate page needed.
✕/client/jobs/[id]Merge job detail into the proposals page. Client doesn't need a separate job detail view.
✕/settings/accountMerge all settings into one /settings page for MVP. Split later when there's enough content to justify tabs.
✕/settings/profileSame — merge into single /settings. Over-segmenting settings pages adds navigation complexity with zero benefit.
✕/notificationsShow notifications inline (dropdown in navbar). A full page for notifications needs high volume to justify. Use in-app toast + email for MVP.
✕/admin/usersMerge into /admin. One admin page with tabs covers disputes, users, and financials for a sub-100 user launch.
✕/admin/disputesSame — merge into /admin dispute tab. Separate admin pages are v2 when dispute volume justifies it.
