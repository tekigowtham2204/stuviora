The trust architecture — solving your #1 fear
Trust is not one problem — it is five separate problems stacked on each other. You must solve all five layers.
1
Identity trust — "Is this student real?"

College email OTP verification on signup. Optional Aadhar-linked KYC for students wanting "verified" badge. Every profile shows: college name, stream, city, year of study.

Build in week 3
2
Skill trust — "Can they actually do this?"

Short AI-graded skill assessment before listing a service (15 min, auto-evaluated). Portfolio samples required. Skill badges from Coursera/NPTEL auto-imported via link.

Build in week 4
3
Payment trust — "Will I get paid / not get scammed?"

Razorpay escrow: client pays upfront into escrow, student gets paid only after client approves delivery. 72-hour auto-release if no dispute. Stuviora holds funds — never touches them.

Critical — day 1
4
Quality trust — "Will the work be good?" ← Your moat

AI quality gate before every delivery. Student submits work → Claude API checks completeness, coherence, brief alignment → gives student a score + fix suggestions → only "pass" submissions reach the client. Client sees "AI-reviewed" badge.

Your moat
5
Track record trust — "Has anyone hired them before?"

First-job guarantee: client gets full refund if first hire from any student fails quality. After 3 completed jobs, "Verified Freelancer" badge unlocks. Review system is mandatory — no delivery closes without a 1-5 star rating.

Drives retention
