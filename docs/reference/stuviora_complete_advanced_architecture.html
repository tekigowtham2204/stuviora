Audit result: 8 systems fully designed · 5 partial · 10 completely new · 4 deferred to v2. The payment split engine, dispute state machine, background job system, tax compliance layer, and matching algorithm are all zero-designed and must be architected before building begins.
Blueprint assumes generic "Razorpay escrow." The correct product is Razorpay Route (Marketplace) — this is a different API that enables automatic percentage splits without manual transfers.
Step-by-step payment flow
1
Client accepts proposal → payment order created
Frontend calls POST /api/payments/create. Server calls Razorpay Orders API with linked account transfer config baked in. Inserts payments row with status PENDING. Returns order_id to client.
2
Client pays via Razorpay Checkout (UPI / card / netbanking)
Full amount (e.g. ₹10,000) captured into Stuviora's Razorpay account. Webhook fires payment.captured. Server verifies HMAC-SHA256 signature, checks webhook_events for duplicate event_id (idempotency), then updates DB.
3
Funds locked → escrow state in DB + both parties notified
Payment record updated to ESCROWED. Insert into platform_ledger as gross credit. Insert commission_events row with status PENDING. Resend fires to student ("You have a new order") and client ("Payment locked — safe to proceed").
4
AI gate passes → client approves (or 72hr Cron auto-releases)
Three paths trigger release: (a) client clicks approve in dashboard, (b) Vercel Cron finds 72hr-expired approvals every 30 min and auto-fires, (c) admin manually releases post-dispute. All three call the same idempotent releaseEscrow(orderId) function.
5
Razorpay Transfer API fires — atomic split, cannot partially fail
Server calls Razorpay Transfer API. Platform 15% stays in Stuviora Razorpay account automatically. 85% transferred to student's linked bank/UPI account. This is one atomic API call — it cannot partially succeed.
Student receives
₹8,500
85% → linked bank / UPI. Direct. No wallet intermediary.
Stuviora keeps
₹1,500
15% stays in Stuviora Razorpay account automatically. Zero manual action.
6
transfer.settled webhook → commission recorded + downstream triggers
Update commission_events status to SETTLED. Update earnings for student. Debit platform_ledger with net (gross minus GST). Fire Inngest events: portfolio.generate + trust.recalculate. Both parties receive completion email.
Webhook event state machine
// app/api/payments/webhook/route.ts switch(event.event) { case 'payment.captured': await verifySignature(req) // HMAC-SHA256 — reject if fails await guardIdempotency(event.id) // check webhook_events table await lockEscrow(paymentId, orderId) await notifyBothParties(orderId) break case 'transfer.created': await logTransfer(transferId, studentId, amount) // transfer_log break case 'transfer.settled': await settleCommission(orderId) await inngest.send('portfolio/generate', {orderId}) await inngest.send('trust/recalculate', {studentId}) break case 'payment.failed': await cancelEscrow(orderId) await notifyFailure(clientId, studentId) break case 'refund.created': // dispute resolved in client's favour await reverseCommission(orderId, refundAmount) await updatePlatformLedger('REVERSAL', -amount) break }
Tax compliance (missing from all files)
GST on platform commission
18% GST on Stuviora's 15% fee once registered. On ₹1,500 commission → ₹270 GST → ₹1,230 net revenue. GST invoice auto-generated per transaction. Stored in tax_events. Required: GSTIN registration.
TDS on student earnings (Sec. 194H)
5% TDS deducted once student earns >₹30,000/year on platform. Platform deducts and deposits to government. Track cumulative in tax_events. Issue Form 16A annually. Requires student PAN (mandatory at onboarding).

None of these exist in any blueprint file. All 10 are new designs. Inngest handles event-triggered async work. Vercel Cron handles timed scheduled jobs.
CRON · every 30 minEscrow auto-release
Finds orders where status = AWAITING_APPROVAL AND approved_at + 72h < NOW(). Fires releaseEscrow() for each. Uses IST timezone. Idempotent — safe to run multiple times. This is the heartbeat of client trust.
EVENT · order.completedTrust score recalculator
Formula: (avg_rating × 0.40) + (on_time_rate × 0.25) + (ai_pass_rate × 0.20) + (response_score × 0.15). Stores result in trust_score_history. Unlocks tier badges (Bronze / Silver / Gold / Platinum). Higher tiers unlock higher-budget jobs.
EVENT · order.completedPortfolio auto-generator
Calls Claude API to generate a case study from: job brief + final submission + client review text. Output: title, problem, approach, outcome, skills used. Stored in portfolio_items. Student can edit — it's a first draft, not final copy.
EVENT · job.postedSmart match notifier
Matching engine scores all eligible students: (skill_overlap × 0.45) + (budget_fit × 0.25) + (trust_score × 0.20) + (availability × 0.10). Top 20 students get push + email. Hard cap: max 3 job alert emails per student per day to prevent notification fatigue.
CRON · daily 2AM ISTCommission reconciler
Fetches Razorpay account balance via API. Compares to sum of platform_ledger net credits. Flags discrepancy > ₹10 to founder via Slack/email. Generates daily revenue digest: GMV, commission earned, Stuviora net, TDS held, pending payouts.
CRON · Monday 9AM ISTWeekly student earnings digest
Sends each active student a weekly summary via Resend: earnings this week, pending orders, new matching jobs, profile views, trust score change. Key retention driver — students who see progress weekly churn 40% less.
EVENT · dispute.raisedDispute escalation timer
Sets a 48hr resolution deadline on every new dispute. If admin hasn't resolved by deadline, Slack alert fires to founder. Commission held in DISPUTE_HOLD status in commission_events until resolved. State machine: OPEN → EVIDENCE_COLLECTION → ADMIN_REVIEW → RESOLVED.
CRON · 1st of monthTDS threshold checker
Calculates each student's cumulative earnings for the financial year. Flags students approaching ₹30,000 threshold. On next payout after crossing: automatically deducts 5% TDS, logs in tax_events, deposits to government account. Generates Form 16A data in April.
EVENT · submission.receivedAsync AI quality checker (Inngest)
All quality checks run via Inngest (not inline) to bypass Vercel's 10-second timeout. For large files (>2MB / DOCX / ZIP), inline execution would always fail. Inngest job has 3 retries with exponential backoff. Result pushed to client via Supabase Realtime channel.
EVENT · user.signupCollege email domain verifier
On student signup, extract domain from email. Check against college_domains table (500+ verified Indian university domains: .ac.in, .edu.in, plus named domains like iitb.ac.in). If domain not found: flag for manual review, block profile creation, send "domain not recognized" email with appeal form.
Row Level Security on every table
Students can only SELECT/UPDATE their own rows in orders, earnings, proposals. Clients only see their own jobs. platform_ledger, commission_events, admin_actions are service_role only — inaccessible from any client session. RLS enforced at the Postgres level, not just in code.
Razorpay webhook signature verification + idempotency
Every webhook: verify x-razorpay-signature header using HMAC-SHA256 with webhook secret. Reject unsigned requests with 400. Before processing, check webhook_events table for duplicate razorpay_event_id. Razorpay retries on 5xx — without this guard, a student gets paid twice.
API rate limiting (per user, per endpoint)
POST /api/proposals: 10/hr/user. POST /api/orders/[id]/submit: 5/day/student. POST /api/ai/quality-check: 3/order (max revisions). POST /api/auth/signup: 3/hr/IP. MVP: in-memory with Redis fallback. v2: Upstash Redis sliding window.
File upload validation
Allowlist MIME types only: PDF, DOCX, PNG, JPG, ZIP. Max 50MB. Strip EXIF from images. Scan ZIP contents for path traversal attacks. Store in private Supabase bucket — generate signed URLs (1hr expiry) per request. Never serve user files from a public CDN URL.
College email allowlist + disposable email blocklist
Maintain college_domains table: 500+ verified Indian university domains. Block known disposable email providers (Mailinator, TempMail, etc.). OTP sent only to allowlisted domains. New domain requests go to admin approval queue with LinkedIn/university link verification.
Secrets management + PII encryption
Razorpay key, Claude API key, Supabase service_role, Resend key — all in Vercel encrypted environment variables. Never in repo. Student PAN numbers and bank account details stored in Supabase Vault (AES-256 encrypted). Never returned in any API response. DPDP Act (India's data protection law) compliance required.
Admin role separation + immutable audit trail
Admin users have a separate role in Supabase Auth custom claims. All admin routes check user.role === 'admin' in JWT at middleware level. Every admin action (dispute resolution, payout override, user ban) is logged immutably in admin_actions table with timestamp + reason. Cannot be deleted.
Contact info gating — privacy by design
Client can see student name + college in proposals — NOT email/phone/social handles. Direct contact details are only visible after order is in ACTIVE status. This protects the platform from disintermediation (clients bypassing Stuviora to hire students directly off-platform).
