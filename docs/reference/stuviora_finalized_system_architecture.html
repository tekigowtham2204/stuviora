Blueprint says "Razorpay escrow" — correct product is Razorpay Route (Marketplace). Only Route enables automatic atomic percentage splits. Standard escrow requires manual transfers and cannot auto-credit Stuviora's account.
6-step auto-split flow
1
Client accepts proposal → Razorpay order created with split config
POST /api/payments/create → Razorpay Orders API with Route transfer config baked in. Inserts payments row as PENDING. Returns order_id to frontend.
2
Client pays (UPI / card / netbanking) → full amount captured
₹X lands in Stuviora Razorpay account. Webhook fires payment.captured. Server verifies HMAC-SHA256 signature then checks webhook_events table for duplicate event ID — Razorpay retries on 5xx; without this guard a student gets paid twice.
3
Funds locked → escrow state written, both parties notified
Payment → ESCROWED. Insert into platform_ledger as gross credit. Insert commission_events as PENDING. Resend fires to student and client. Supabase Realtime updates both dashboards live.
4
Release trigger — three paths, one idempotent function
Path A: Client clicks Approve. Path B: Vercel Cron fires every 30 min, finds 72hr-expired orders → auto-releases. Path C: Admin manually releases post-dispute. All three call releaseEscrow(orderId).
5
Razorpay Transfer API → atomic split (cannot partially fail)
One API call. Platform 15% stays in Stuviora Razorpay account automatically. 85% transferred to student's linked bank/UPI. Atomic — either both succeed or neither does. No intermediate wallet needed.

Critical design gap: the blueprint never addresses file extraction. Claude cannot read a PDF — it receives bytes. Without an extraction step, the quality gate fails silently on every real submission.
Async extraction → evaluation → routing (Inngest — not inline)
1
Student submits files → API returns immediately
POST /api/orders/[id]/submit uploads files to Supabase Storage (private bucket) and returns REVIEW_IN_PROGRESS within 2s. Never calls Claude inline — Vercel times out at 10s for large files.
2
Inngest event fired → async worker picks up (3 retries, exponential backoff)
inngest.send('ai/quality.check', { orderId, filePaths }) — non-blocking. Inngest manages retries. Supabase Realtime will push the result to the student's browser when complete.
3
File extraction by type
.pdf → pdf-parse → text string
.docx → mammoth → HTML → strip tags
.png/.jpg → Claude Vision API → text description
.py/.js/.ts → raw string (code is already text)
.zip → unzip → loop each file through the above
4
Claude API call — strict JSON output enforced
System: "Respond only in JSON. No prose before or after." User prompt includes job brief + extracted content (capped at 8,000 tokens). Forces schema: score 0–100, verdict PASS/FAIL, brief_alignment, completeness, quality, issues[], suggestions[].
5
Score routed → verdict delivered via Realtime
PASS (≥70): Client notified. AI-reviewed badge applied. Delivery → AWAITING_APPROVAL.
FAIL (<70): Issues + suggestions shown to student only. Resubmit enabled. 3rd consecutive fail → admin queue + commission held.
Quality gate prompt structure
JOB BRIEF: Title: ${job.title} Description: ${job.description} SUBMITTED WORK: ${extracted.slice(0, 8000)} Respond ONLY with this JSON: { score: 0-100, verdict: "PASS" | "FAIL", brief_alignment: 0-40, completeness: 0-30, quality: 0-30, issues: string[], suggestions: string[], ai_reviewer_note: string }

All 10 background jobs are absent from the original blueprints. Without these, the platform cannot function: escrow never auto-releases, trust scores never update, students never get matched to jobs.
Inngest — event-driven (7 workers)
EVENT · submission.receivedAsync AI quality checker
Bypasses Vercel 10s limit. Extracts files by type, calls Claude, stores verdict in ai_reviews, pushes result via Supabase Realtime. 3 retries with exponential backoff. If all 3 fail → status REVIEW_ERROR, admin alerted.
EVENT · order.completedTrust score recalculator
Formula: (avg_rating × 0.40) + (on_time_rate × 0.25) + (ai_pass_rate × 0.20) + (response_score × 0.15). Stores delta in trust_score_history. Unlocks tier badges Bronze → Silver → Gold → Platinum. Higher tiers unlock higher-budget jobs.
EVENT · order.completedPortfolio auto-generator
Calls Claude to draft a case study from: job brief + final submission + client review text. Stored in portfolio_items as a draft. Student edits before publishing. Zero effort — passive portfolio building on every completed job.
EVENT · job.postedSmart match notifier
Scores all eligible students: (skill_overlap × 0.45) + (budget_fit × 0.25) + (trust_score × 0.20) + (availability × 0.10). Notifies top 20 via in-app + email. Hard cap: max 3 job emails/student/day to prevent fatigue. Stores in matching_scores.
EVENT · dispute.raisedDispute escalation timer
Sets 48hr resolution deadline. Slack alert to founder if unresolved. Commission held in DISPUTE_HOLD in commission_events. State machine: OPEN → EVIDENCE_COLLECTION → ADMIN_REVIEW → RESOLVED. Commission reversed or released based on admin decision.
EVENT · user.signupCollege domain verifier
Checks email domain against college_domains table (500+ verified Indian university domains). Unknown domain → manual review queue, blocks profile creation, sends appeal email. Prevents fake students with Gmail accounts.
EVENT · transfer.settledTax event logger
Records GST (18% of platform commission) in tax_events. Checks student's YTD earnings — if next payout crosses ₹30,000 threshold, flags for 5% TDS deduction. Generates Form 16A data in April. Required for Indian tax compliance.
Vercel Cron — scheduled (3 jobs)
CRON · every 30 minEscrow auto-release
Finds orders where status=AWAITING_APPROVAL AND confirmed_at + 72h < NOW(). Calls releaseEscrow() for each. Fully idempotent — safe to run on overlapping cycles. IST timezone. This is the heartbeat of client trust on the platform.
CRON · daily 2AM ISTCommission reconciler
Fetches Razorpay account balance via API. Compares to sum of platform_ledger net credits. Flags any discrepancy >₹10 to founder via email. Generates daily founder digest: GMV, commission earned, GST liability, TDS held, pending payouts.
CRON · Monday 9AM ISTWeekly student earnings digest
Sends each active student a personalized weekly summary via Resend: earnings this week, open orders, new matched jobs, trust score change, profile views. Students who see progress weekly churn 40% less. Key retention mechanism — takes zero student action.
Row Level Security on every table
Students can only SELECT/UPDATE their own rows in orders, earnings, proposals. Clients only see their own jobs. platform_ledger, commission_events, admin_actions are service_role only — completely unreachable from any client browser session. RLS enforced at Postgres level, not just application code.
Razorpay webhook — HMAC-SHA256 verification + idempotency guard
Every webhook verifies x-razorpay-signature header. Reject unsigned with 400. Before any DB write, check webhook_events for duplicate event ID. Razorpay retries on 5xx — without this, a student gets paid twice. This guard is non-optional.
API rate limiting — per user, per endpoint
POST /api/proposals: 10/hr/user. POST /api/orders/[id]/submit: 5/day/student. POST /api/ai/quality-check: 3/order (enforces revision limit). POST /api/auth/signup: 3/hr/IP. Upstash Redis sliding window counters.
File upload validation — MIME + size + content scanning
Allowlist: PDF, DOCX, PNG, JPG, ZIP only. Max 50MB. Strip EXIF from images. Scan ZIP contents for path traversal attacks. Store in private Supabase bucket — never a public CDN URL. Signed URLs with 1hr expiry generated per download request.
College email allowlist + disposable email blocklist
500+ verified Indian university domains in college_domains table. Block known disposable providers (Mailinator, TempMail, Guerrilla Mail). Unknown domains go to admin approval queue with LinkedIn verification. OTP sent only to allowlisted domains.
PII encryption + secrets management (DPDP Act 2023 compliant)
Student PAN numbers and bank account details encrypted at rest in Supabase Vault (AES-256). Never returned in any API response. All service keys (Razorpay, Claude, Supabase service_role, Resend) in Vercel encrypted environment variables — never in code or repo.
Admin role isolation + immutable audit trail
Admin role in Supabase Auth custom JWT claims. All admin routes verified at middleware level. Every admin action (dispute resolution, payout override, user ban) logged immutably in admin_actions with timestamp + reason. Cannot be deleted by any role including admin itself.
Contact info gating — anti-disintermediation by design
Student email, phone, and social handles hidden until order reaches ACTIVE status. Client sees only name + college in proposals. Prevents clients from hiring students directly off-platform to bypass Stuviora's commission — a critical revenue protection mechanism.
